AI Integration · Serverless · Web App

SUDOKOO

SUDOKOO is an AI-powered web app that takes a photo of a Sudoku puzzle and turns it into an interactive game. It uses Amazon Bedrock with Anthropic's Claude to read the puzzle from the image.

Amazon Bedrock Lambda CloudFront API Gateway S3 Node.js

This app is no longer deployed. The code and infrastructure template are on GitHub, and a rebuild would move from Node.js 18 and Claude 3.5 Sonnet to a current Lambda runtime and Claude model.

The Problem

My girlfriend had kept a Sudoku puzzle from a newspaper clipping for years. She wanted to finish it herself, so I couldn't write on it. I decided to digitise it so I could try solving it too, and that small problem was the starting point for this project.

The project was also a chance to learn how to integrate AI into a working application on AWS, specifically with Amazon Bedrock.

Architecture Overview

The system was a serverless web application. API Gateway and a Lambda function sent a base64-encoded image to Amazon Bedrock, where Claude extracted the Sudoku grid from the image. Lambda checked that the grid was a valid, solvable puzzle and returned it to the browser as a playable game.

The camera scan is the main input mode. The app also includes a client-side puzzle generator, so new games are created in the browser with no API call. The game engine (pencil marks, keyboard navigation, move validation, a timer and conflict highlighting) runs entirely client-side and works independently of the AWS backend.

Key Design Decisions

Decision · AI Service Selection

Bedrock over Rekognition or a custom model. Rekognition is designed for object detection and facial recognition. Extracting a structured 9×9 grid with cell values is not its intended use case. A custom model would require training data and significant upfront investment. Bedrock with Claude accepts a natural language prompt describing the extraction task and returns the result.

Decision · No VPC

Lambda runs without VPC attachment. This workload only needs to call managed AWS services such as Bedrock and S3, so Lambda can use AWS-managed networking and public regional service endpoints without subnets, route tables, NAT Gateway, or VPC endpoints. Adding VPC configuration would increase complexity and may add cost through NAT Gateway or PrivateLink endpoints, with little security benefit for this workload unless the function needs access to private VPC resources.

Decision · CloudFront + S3 with OAC

Private S3 bucket with Origin Access Control. The bucket policy grants read access only to this specific CloudFront distribution, identified by the distribution's ARN. Users access files only through CloudFront, not directly from S3. This prevents bypassing the CDN and avoids unexpected S3 data transfer charges.

Decision · WAF removed

WAF deployed then removed. AWS WAF was initially configured with managed rules for SQL injection, XSS and the core rule set. At $8/month for 3 active rules on a single-user portfolio project, the cost was disproportionate.

Honest Assessment

The AI extraction worked approximately 50% of the time. It worked on the puzzle from my girlfriend's newspaper clipping, which was the original goal. The two main failure modes were grid alignment errors (correct digits placed in adjacent cells) and character recognition errors (misread digits, most commonly 1 read as 7). The validity check rejects grids with duplicate values in a row, column or box, so those are not loaded into the game. Some misread digits can still produce a grid that passes validation but does not match the original puzzle.

For a learning project, 50% was acceptable. My goal was to learn how to integrate AI to solve this problem. For a production application I would use tool use or structured outputs on a current Claude model instead of free-text parsing, and add a validation step that rejects and re-requests extractions below a confidence threshold.

Manual deployment through the AWS console was a deliberate choice to build deeper understanding of each service's configuration options. The trade-off was slow iteration: uploading new frontend files and invalidating CloudFront manually every time became tedious. A CI/CD pipeline (GitHub Actions → S3 sync → CloudFront invalidation) would be the first improvement if I rebuilt this project.
